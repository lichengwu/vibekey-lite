## 晚间：灯效渲染根因破解（社区代码 + 单状态对照实验，用户配合）

- **社区金矿**：`MrCroxx/olanzi`（GitHub，AU05 开源驱动）的 `DeviceLighting.swift` 揭示关键规则——**每条 SET 帧必须携带完整四灯记录**（mode+brightness+4×5字节 tuples），mask 只选本次修改字段；只填单槽其余清零会被固件清表。这就是 11-18 "只存不渲染"的真正根因（之前探针都是单槽零填充）。
- **语义确证**：mode 0=全灭/1=全亮/2=工作模式；wt 0=关/1=常亮/2=呼吸；亮度 0..20；**idx0=键1(语音)/idx1=键2/idx2=键3/idx3=旋钮**（Olanzi UI 源码）。渲染由"新写入"触发，重复同状态不发命令。
- **本机实测**（全量载荷、心跳在线、Lite 开/关无差异）：① 旋钮 idx3 常亮 wt=1 可靠渲染（全灭→亮对照确认）；② 三个按键灯 idx0/1/2 工作模式下均不渲染（常亮+呼吸都黑，GET 读回一致）；③ 旋钮呼吸 wt=2 也不渲染（新写入仍黑）。只有旋钮常亮可控。
- **探针修复**：ledstate.swift 的 IOHIDManager 是函数局部变量被 ARC 释放导致收不到报告→存到全局 Box.manager 修复。设备休眠需物理按键唤醒（dongle 06 03 0a 查询 status=00 判离线）。
- **M2 修正结论**：可靠表达 = 全局 mode 0/1 开关 + 旋钮单灯常亮开关（全量载荷写 idx3 wt=1/0）。呼吸不可用，"思考中"可用旋钮闪烁模拟。
- 设备已恢复基线（wt 2/0/0/1、亮度7、mode2），Lite 已重启。结论写入 docs/protocol.md「Correction: full-payload SET frames DO render」节。

## 深夜：workTime 闸门破解，三灯独立可控（用户配合单状态对照）

- **第二根因 workTime**：按键灯 wt=1 常亮在 workTime=10（出厂值）下只亮约 10 秒就自动灭——之前所有"按键灯不渲染"的观察都在 10 秒窗口之后，是假象。写 workTime=255（必须用 mask 0x08 专用帧，全量载荷里塞 255 会被忽略）后按键灯持续常亮。Olanzi 禁止改 workTime 把这个杠杆藏住了。
- **写入顺序**：workTime(0x08)/breatheLevel(0x10) 先 → 亮度(0x20/0x40) → workType(0x04) 最后当激活开关。
- **最终可控能力**：idx1(中键)、idx2(下键)、idx3(旋钮) 三颗灯独立常亮开关（workTime=255）。idx3=旋钮 再次隔离确认。
- **idx0(语音键) 工作模式不可控**：wt=1/2、breatheLevel 2/6、亮度 15/20、workTime 10/255、wt 3..7 扫描全黑；但 mode 1 全亮时四颗全亮（硬件正常）。与 Studio 一致——updateIndicatorLightByState 只写 idx 1/2/3，从不碰 idx0。语音键灯是录音指示，归麦克风状态管，不归 AI 状态灯表。
- **反汇编佐证**：UlanziDeck::updateIndicatorLightByState(HookFiredEvent) 循环 idx 1/2/3 调 onSetIndicatorLightWorkModeType；LedIndicator::getConfigForState 状态表 idle/attention/error/sleeping=待机、thinking/working/sweeping=工作中、notification=工作中(需审批)，配置值多为 1。
- **M2 最终方案**：三灯独立编码状态（idle 全灭 / working 旋钮常亮 / attention 中+下常亮 / thinking 旋钮闪烁）+ 全局 mode 0/1。呼吸 wt=2 在本机仍不渲染，用闪烁模拟。
- 设备已恢复基线。结论写入 docs/protocol.md「Second correction: workTime is the render gate」。
