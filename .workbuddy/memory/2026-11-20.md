## 语音键灯（idx0）最终定论：固件按键事件反馈灯，主机不可控

- **决定性观察（用户）**：语音键灯在"按下→松开"瞬间闪一下，工作模式下由固件自驱。与官方说明书"工作模式灯光根据实际物理操作反馈"吻合。之前疑似 LedEffect 生效的闪烁实为用户按键触发。
- **三条死路全部实测排除**：① mic UI flick（01 06 22/24）ACK 不存储、mode 1/2 无渲染、主程序零引用；② mic enable（01 01 2A）会破坏语音键正常功能（已恢复，勿用）；③ LedEffect RGB 通道（01 06 11/39，带 R/G/B 颜色）ACK 且逐字节存储（出厂 mode=6 speed=1 bright=0xB0），但 mode 0..7 扫描全黑、support 查询=0、主程序零引用——疑似 Dial/TC002 彩灯产品族接口。
- **官方 hooks 管线摸清（本机明文源码）**：`~/Library/Application Support/Ulanzi/UlanziDeck/ustudio-cli/hooks/mappings.js` 有 9 种 Agent 的事件→状态映射（UserPromptSubmit→thinking、PreToolUse→working、Stop→attention、Notification→notification、PreCompact→sweeping、SessionStart→idle、SessionEnd→sleeping、*Failure→error）。device-hook.js 构造 ai-tool-state JSON；WiFi 设备 HTTP POST /events，USB 走 Studio 本地 socket。Studio 收事件后仍只写 idx1/2/3。**这份映射表可直接抄进 M2**。
- M2 能力边界不变：idx1/idx2/idx3 三灯独立常亮（workTime=255）+ 全局 mode 0/1；idx0 留给固件当按键反馈。
- 设备已恢复基线，结论写入 docs/protocol.md「Voice-key LED final verdict + dead-end channels」。
