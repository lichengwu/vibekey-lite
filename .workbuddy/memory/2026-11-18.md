## 晚间：灯效渲染语义实验（约 23:00-23:30，用户配合观察）

- **0x48 记载纠错**：反汇编 Ulanzi_Studio.dylib 确认所有 `setDeviceIndicatorLight*` setter 全部用 0x88（w8=0x04880B01 → `01 0B 88 04`）；0x48 属 DialMini 组（setDeviceDialMiniLed*）。hooks SET = `01 0B 89 04 <status@4>`，AU05 应答但不存储（GET 恒 0），死路。
- **SET 帧字节级确证**：workModeType 的 payload 偏移 = idx*5，值在 8+5*idx；currentMode 帧掩码 0x01 值@6；allOnBright 掩码 0x02 值@7。
- **核心结论：AU05 存储但不渲染 per-LED tuple**。实测：wt 0~5 全灯扫描（参数先发/模式后发两种顺序）、单灯 wt=2 10s 窗口、全灯 wt=1 亮度15——主机在线期间全部黑灯。GET 回读证明值都存进去了。
- **全局模式实时渲染**：mode 0=全灭、mode 1=全亮（多次复现）；mode 2 及 3~9 黑。用户观察用"1 秒全亮分隔闪"锚点法（markersweep 探针）。
- **旋钮灯原生行为**：探针退出（原生模式无心跳）后旋钮灯自亮，与 tuple 内容无关（wt=1/wt=2 配置下都亮）——固件自身空闲灯效，未找到可控帧。
- **M2 落地方案**：唯一可靠表达 = 全局 mode 1（全亮，工作中/需关注）vs mode 0（全灭，空闲）开关。per-LED 表在此固件上是只写存储。
- 设备已精确恢复基线（wt 2/0/0/1、time=10、bl=2、bb/ab=7、mode 2，ledrestore 探针+GET 复核）。
- 结论已写入 docs/protocol.md「Frame provenance and rendering semantics」节。
